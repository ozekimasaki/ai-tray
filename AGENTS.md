# QuotaBar — agent notes

## Windows + Bun dev setup

```sh
bun install -g @native-sdk/cli@0.9.3   # lands in ~/.bun/bin (add to PATH)
mise use -g zig@0.16.0                 # required; CLI can't fetch zig on Windows
SCRIPTC_CC=zigcc native dev            # zigcc avoids missing-clang error
SCRIPTC_CC=zigcc native build          # ReleaseFast → zig-out/bin/quotabar.exe
```

- `native dev` builds Debug — scrolling/layout is noticeably slower. Use `native build` + run the exe for real perf testing.
- `native check` is broken on Windows: it passes backslash paths to an import resolver that only understands `/`, so `components/...` imports fail. Use forward slashes: `native markup check src/windows/compact.native ...`. Build/dev are unaffected.

## Scroll / rendering on Windows

- All three windows are `transparent: false` (was `true`). Layered windows (`WS_EX_LAYERED`) cannot composite the child HWND's Direct2D packet surface → every frame fell back to CPU raster + full-window `UpdateLayeredWindow`, causing scroll lag. Opaque windows use the GPU packet path (~16ms frames, much lower memory).
- Wheel scrolling is patched in the installed SDK for browser-style smooth scroll (`tools/patch-native-sdk-scroll.sh`, re-apply after reinstalling the CLI): `wheel_multiplier=0.15` (6px instant), `wheel_velocity_scale=15`, `deceleration_per_second=2e-7` (~0.3s ease-out, ~45px/notch total), and velocity ACCUMULATES across rapid notches (`next.velocity += delta * scale` in `applyWheelWithRubberband`). SDK defaults were multiplier=1, velocity_scale=60, decel=0.86, velocity overwrite — that flung hundreds of px per notch.
- Windows has no native scroll driver in the SDK — scrolling is always the engine-side path.

## Services: Windows fetch gotchas

- scriptc's typed `JSON.parse` **rejects `null`** wherever the declared (or inferred) type is an object: `expected object | undefined at $.seven_day_oauth_apps, got null`. Every API body goes through `parseJson`, which runs `dropNullPairs` first — don't hand a raw response body to `JSON.parse` in a service.
- Fast loop for service code (no 10-minute app build): copy `src/snapshot.ts` + `src/services/*.ts` into a temp dir, add a `main.ts` that calls `fetchOne`, then `SCRIPTC_CC=zigcc node node_modules/scriptc/dist/main.js run main.ts`. Same runtime as the packaged `quotabar_services.exe`.
- Reading card text without clicking: `SCRIPTC_CC=zigcc native dev -Dautomation=true`, then `native automate menu-command app.refresh` / `app.dashboard`, then grep `role=text name="` in `.zig-cache/native-sdk-automation/snapshot.txt`. The ReleaseFast build did not publish a snapshot here — dev does.
- `errorKind: "not_found"` / `"migrated"` renders the **core-side hint** (`settingsHint` in `src/core.ts`), not the service's `errorText`. Return `"auth"`/`"unknown"` when the service's own message should reach the card.
- The compiled child-process spawn resolves a bare command to `<name>`, `<name>.com`, `<name>.exe` only — npm/pnpm `.CMD` shims (`agy.cmd`) are never found on Windows. `agy` installs to `%LOCALAPPDATA%\agy\bin\agy.exe` and the installer writes that into the *registry* user PATH, but already-running Explorer/terminals keep the old env block, so `agy` stays unresolved until re-login. **There is no headless usage output**: `agy -p /usage` does not expand the slash command — it sends the literal text "/usage" to the model, which (with `--dangerously-skip-permissions`) spent 107k tokens / 54s explaining Git, and (without it) auto-denies the `command` tool. So QuotaBar never spawns agy; the card only reads the app token + Gemini OAuth. CLI auth state is visible in `~/.gemini/antigravity-cli/log/cli-*.log` (`applyAuthResult: email=..., authMethod=consumer` vs `You are not logged into Antigravity`), and an agy login does NOT refresh `~/.gemini/oauth_creds.json`.
- **Antigravity quota comes from the IDE's local Language Server, not the cloud API.** `languageServerEndpoints()` in `src/services/usage.ts` finds the process whose command line carries `--csrf_token`, reads its listening 127.0.0.1 ports, and `POST http://127.0.0.1:<port>/exa.language_server_pb.LanguageServerService/RetrieveUserQuotaSummary` with `Content-Type: application/json`, `Connect-Protocol-Version: 1`, `X-Codeium-Csrf-Token: <token>` and body `{}`. Response is `response.groups[].buckets[]` with `displayName`/`remainingFraction`/`resetTime`; the two HTTP/HTTPS ports per process answer differently, so try every port. `GetUserStatus` on the same port has no quota fields. `ideType` on the cloudcode-pa assist endpoint: `INTEL_IDE`/`ANTIGRAVITY_IDE` → 400, `ANTIGRAVITY` → 200, and cloudcode-pa `retrieveUserQuota` 403s for this account anyway ("You do not have a valid license of this product"). Reference implementation: github.com/skainguyen1412/antigravity-usage. **Consequence: the card only works while the Antigravity IDE process is running.**
- **An expired Claude CLI token is rescuable with its own `refreshToken`**: `claudeRefreshedToken()` POSTs `grant_type=refresh_token` to `https://console.anthropic.com/v1/oauth/token`. The `client_id` must be the one that minted the token — Claude Code 2.1.72 embeds `9d1c250a-e61b-44d9-88ed-5944d1962f5e` (find it by scanning the installed bundle for `client_id='<uuid>'`; the widely-circulated `92a987f2-...` returns `400 Client with id ... not found`). The credential file is never rewritten, so the result is cached in module state (`claudeFreshToken`) — refreshing on every 120s cycle invites 429. `api.anthropic.com/api/oauth/usage` rate-limits readily; unmapped HTTP statuses used to surface as `Network error`, which sent everyone chasing the network stack.
- Markup bindings cannot reach into a value: `{b.resetLabel.length > 0}` fails at build with `binding does not name a field on the loop item`. Put the decision in the record (e.g. `CardBar.hasReset`) and test that. `native markup check` passes it silently while `zig-out/model-contract.zon` is stale (it prints the staleness warning and checks structurally only) — only `native build` catches it.
- If `quotabar.exe` and `quotabar_services.exe` come from different source revisions, every card shows `{"kind":"service_host","message":"service host exited or rejected the request"}` — the host carries the contract. Rebuild both together before believing a service regression.

## Tray and frame pacing on Windows

- `tools/patch-native-sdk-tray.sh` (run after every CLI reinstall, like the scroll patch): the SDK's tray left-click branch emitted the activation command **and** called `showTrayMenu()`, whose `TrackPopupMenu` nested loop stole foreground and stalled the frame pump — that was the "one beat delay" when opening the panel. The patch keeps the menu on right-click only. Backup: `webview2_host.cpp.bak` next to the source.
- Never judge perf from an `-Dautomation=true` build: it writes `snapshot.txt` + `accessibility.txt` on every presented frame (measured: 4.4% CPU closed / 11.4% open vs **0.9%** clean, WS 62MB, 0.35 frames/s idle — the engine skips clean frames).
- Scroll cadence with real wheel input on the clean ReleaseFast build: **p50 28ms (~36fps)** at 120ms notch spacing, p50 38ms at 40ms spacing, input→frame latency 9-23ms. App-side work is not the limit (`emit` 0.3ms, `present` 1.7ms, `host_draw` 1.6ms per frame); the 16.7ms one-shot timer grid plus a blocking vsync present quantizes to ~2 slots. Reproduce with `tools/measure-scroll-fps.sh` (needs an automation build for `profile on`; the gap numbers hold).
- The runtime event log is unbounded: `%LOCALAPPDATA%\dev.quotabar.app\Logs\native-sdk.jsonl` grows ~306 B/s ≈ 26 MB/day.
